## 2. 项目是什么（30 秒版）

### 2.1 一句话

**DevFlow AI 是一个面向研发团队的 AI 协作平台**：把 GitHub 上的 Issue / PR / CI / 代码 / 文档全部同步到本地，然后用 Agent + RAG 回答"这个 Issue 该怎么处理""这个 PR 能不能合""这个 CI 为什么挂了"。

### 2.2 业务痛点（课程原话）

> 研发协作最痛苦的，从来不是没有信息，而是**信息太多且太散**。Committer 变成了"人肉路由器"。

### 2.3 四步业务主线

```
定位（这是哪个 Issue/PR/CI）
  → 取证（翻历史 Issue、代码、文档、CI 日志）
  → 判断（结论 / 优先级 / 负责人 / 能不能合）
  → 沉淀（写回记忆，下次能查到）
```

### 2.4 技术栈

## 5. 工作约定（必须遵守，这是几个月磨合出来的）

### 5.1 分批推进，每批必验证

**不要一次改很多文件。** 用户接受分批，但不接受"改坏了"。

每一批的固定动作：

```
1. 读文件（Read）
2. 写文件（Write 或 Edit）
3. 语法检查：py_compile
4. ★ AST 逐部件比对（关键！见 5.3）
5. 应用导入：from app.main import app
6. 跑相关测试（必要时全量）
7. 更新 docs/注释进度.md
8. 写 .workbuddy-ai/memory/YYYY-MM-DD.md
9. present_files 交付
```

### 5.2 大文件分段落写入

超过 1000 行的文件，不要一次 `Write` 全部内容（容易出错）。

**做法**：
1. `Write` 第 1 段，末尾留占位符 `# __PART2__`
2. `Edit` 把占位符替换成第 2 段 + `# __PART3__`
3. 最后检查 `grep -n "__PART" file.py` 确认无残留

### 5.3 ★ AST 逐部件比对（整套方法的核心）

**这是最重要的验证手段，绝对不能省。**

```bash
cd /Users/mumu/Documents/DevFlow-AI/backend

# 首次需要提取备份（项目不是 git 仓库，唯一回滚手段）
tar -xzf ../.workbuddy-ai/backups/app-20261022-172635.tar.gz -C /tmp/orig backend/app

# 比对单个文件
/usr/bin/python3 - <<'PY'
import ast, difflib
def strip_ds(tree):
    """去掉所有 docstring，只留逻辑"""
    for node in ast.walk(tree):
        if isinstance(node, (ast.Module, ast.ClassDef, ast.FunctionDef, ast.AsyncFunctionDef)):
            b = node.body
            if b and isinstance(b[0], ast.Expr) and isinstance(b[0].value, ast.Constant) and isinstance(b[0].value.value, str):
                node.body = b[1:] or [ast.Pass()]
    return tree
def parts(p):
    t = strip_ds(ast.parse(open(p, encoding="utf-8").read()))
    return {f"{type(n).__name__} {getattr(n,'name','?')}{i}": ast.dump(n, include_attributes=False)
            for i, n in enumerate(t.body)}

o = parts("/tmp/orig/backend/app/services/rag/qa.py")
n = parts("app/services/rag/qa.py")
miss, extra = set(o)-set(n), set(n)-set(o)
diff = [k for k in o if k in n and o[k] != n[k]]
print(f"部件 {len(o)}→{len(n)} | 缺失{len(miss)} 多出{len(extra)} 不同{len(diff)}")
if miss: print(" 缺失:", miss)
if extra: print(" 多出:", extra)
for k in diff:
    print(f"--- {k} ---")
    a = o[k].replace("),", "),\n").split("\n"); b = n[k].replace("),", "),\n").split("\n")
    for line in list(difflib.unified_diff(a, b, lineterm="", n=1))[:20]: print(" ", line)
print("✅ 完全一致" if not (miss or extra or diff) else "⚠️ 有差异")
PY
```

**为什么必须做**：这套方法在整个工程中抓到了 **2 处真实 bug**（签名相同、语法正常、肉眼绝对看不出）：

1. `services/rag/qa.py` —— 漏了 `.strip()`，抽取式答案尾部会残留空白和 `#`
2. `services/rag/chunking.py` —— 把 `page_match` 内联进 `if`，导致 `re.match` 被调两次

**只比签名是不够的**，必须比到 AST 节点。

### 5.5 pytest 的唯一正确跑法

**必须用唯一的 basetemp 目录**，否则会被沙箱拦截（报 `sitecustomize.py: PermissionError`）：

```bash
cd /Users/mumu/Documents/DevFlow-AI/backend
BT=".pytest_$(date +%H%M%S)"
.venv/bin/python -m pytest app/tests -q --basetemp="$BT" 2>&1 | tail -6
```

**原因**：pytest 默认在系统临时目录 `/private/var/folders/.../pytest-of-root` 创建文件，被沙箱拦。

所以**每次用新目录名**。`.gitignore` 已加 `.pytest_tmp*/`。

### 5.7 ★ 前端（TS/TSX）的等价性验证

后端用 `ast.dump` 去 docstring 比对，前端没有现成的 AST 工具，等价做法是 **去注释后比对编译产物**：

```bash
cd /Users/mumu/Documents/DevFlow-AI/frontend
TSC=node_modules/.bin/tsc
# 旧文件从备份解出来：tar -xzf ../.workbuddy-ai/backups/frontend-*.tar.gz -C /tmp/fe_orig
$TSC /tmp/fe_orig/frontend/<path> --removeComments --target ES2017 --module esnext \
     --moduleResolution bundler --skipLibCheck --noResolve --jsx react-jsx --outDir /tmp/old
$TSC <path>                       --removeComments --target ES2017 --module esnext \
     --moduleResolution bundler --skipLibCheck --noResolve --jsx react-jsx --outDir /tmp/new
diff /tmp/old/<name>.js /tmp/new/<name>.js   # 无输出 = 只改了注释
```

**三个必须注意的点**：
1. `.tsx` 必须加 `--jsx react-jsx`，否则不产出 JS（`preserve` 模式只留 JSX）
2. 纯类型文件（如 `lib/types.ts`）没有 JS 产物，改比 `--declaration --emitDeclarationOnly` 的 `.d.ts`
3. `--skipLibCheck` 必加：`@types/node` 在本项目里有一堆 `undici-types` 的既有报错，会淹没真正的差异

**全项目类型检查**：`node_modules/.bin/tsc --noEmit -p .`（当前基线：0 错误）

**注释陷阱（本批踩到）**：块注释里出现 `*/` 会提前终止注释。我写 `app/**/page.tsx` 时踩了一次，
后面的中文全被当成代码。**写路径时不要用 `**/` 这种写法。**

### 5.8 macOS 环境注意

- **BSD grep 不支持 `\s`** → 用 `[[:space:]]` 或改用 Python
- **BSD sed 的 `-i` 需要跟空字符串** `sed -i '' 's/a/b/' file`，但中文路径容易出问题 → **优先用 Python 做文本替换**
- **没有 `timeout` 命令** → 用 `run_in_background` 或省略
- 系统 Python 是 `/usr/bin/python3`（3.9），项目 Python 是 `backend/.venv/bin/python`

```python
def compress_messages(messages, max_tokens):
    """把消息列表按预算裁剪，保留最近的若干条。

    【调用链】追这个函数会进入：
        1. clip_to_token_budget()  → 单条消息超长时截断
        2. estimate_tokens()       → 算每条消息的成本

        入：messages（来自 chat_messages 表）、max_tokens（预算）
        出：(kept, stats) → kept 拼进 prompt；stats → 前端"上下文用量"面板
    【关键规则】
        1. 从【后】往前保留 —— 最近的消息最重要
        2. 单条消息最多占预算的 1/3
    """
```

**「被谁调用」是反向索引** —— 用户想改某个函数时，能立刻知道会影响谁。这是他最满意的设计。

```python
    connect（系统的最上游，数据流 1 的起点）
      前端"连接仓库" → 三种模式判定 → GitHubClient.get_repo() 验证
      → repositories 表（token 加密） → sync_repository() → 后台建代码图谱

【要点】
    1. 连接是 upsert：按 full_name 查，存在就更新
    2. token 一定加密存，从不回传前端
"""
```

### 6.4 写注释的三条铁律

1. **只解释「为什么」，不解释「是什么」**
   - ✅ `# 用 compare_digest 而不是 == ：防时序攻击`
   - ❌ `# 比较两个字符串`

2. **业务规则必须写"违反了会怎样"**
   - ✅ `# 必须用 repo_id + github_issue_id 双条件，否则两个仓库的 #42 会串线`

3. **技术陷阱要标出来**
   - ✅ `# Milvus 的 VARCHAR max_length 单位是【字节】不是字符，中文 3 字节/字`

## 10. 这个项目里最值得讲的设计（如果用户问"有什么亮点"）

按"面试价值"排序：

1. **AI 写 GitHub 的三重闸门**（`action_drafts.py`）
   状态机单向 + 权限分两级（create vs approve）+ 失败也写审计。
   核心思想：**AI 不能直接产生副作用**。

2. **上下文投影而非累积**（`chat_agent.py`）
   每轮只重建 System + Human 两条消息，历史/证据/观察全部拼进 user_prompt 字符串。
   好处：token 消耗可预测，不会被历史撑爆。

3. **压缩只改视野不删历史**（`chat_memory.py`）
   `recent()`（模型看的投影）vs `timeline()`（用户看的完整流水）。
   压缩边界是一条 `role=system` 的假消息，meta 里存"保留哪些消息、原文用哪个工具能查回来"。

4. **父子块检索**（`chunking.py`）
   小切片检索（准）→ `parent_id` 拼回大块（全）。
   用小的命中，用大的回答。

5. **两层评测**（`ragas_runner.py`）
   RAGAS 语义分（能测质量但会飘）+ 硬规则八项断言（可复现但只测对错）。
   硬规则不过 = 一定失败，不管 RAGAS 多少分。

6. **数据分流规则**（`source_policy.py`）
   什么进 RAG、什么直查、什么都不进（`code_file` 两边都不在 —— 源码走工作区实时读）。
   理由：源码有精确结构，语义检索不如 grep；且频繁修改会让向量过期。

7. **工具白名单即权限边界**（`skills/registry.py`）
   技能激活后，调白名单外的工具会被 ChatAgent 强校验拦下。
   所以 SKILL.md 的 `tools` 字段不是"建议"，是"沙箱"。

8. **目标解析绝不回退**（`chat.py`）
   用户说"分析 Issue #42"，本地没同步到 #42 时抛 422，**绝不悄悄分析最新的那个**。
