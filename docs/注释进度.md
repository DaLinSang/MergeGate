## 注释风格约定（v5：services 专用「调用链地图」，2026-10-23 新增）

> 适用于 `services/` 里带复杂业务逻辑的代码（数据模型/契约仍用 v4）。
> 目标：**追源码之前，先在注释里看到"我会追到哪些函数"**，不用一层层点进去找。

### ① 文件头必须有「函数地图」

按业务顺序编号，直接告诉读者"按 ①→⑨ 读就是一条完整数据流"：

```python
"""
上下文压缩与 token 预算
======================

【业务定位】...
【数据流向】上游（谁调它）/ 下游（它依赖谁）
【核心规则】1. 2. 3.

【本文件函数地图】（追源码时按 ①→⑨ 顺序读，就是一条完整数据流）
    ① 算 token      estimate_tokens()
    ② 算窗口        model_context_window_tokens() → effective_context_window_tokens()
    ③ 判压力        calculate_context_pressure() → _thresholds_for_window()
    ...
    辅助工具（被上面反复调用，建议先读这几个）：
        clip_to_token_budget() / _unique_preserve_order() / ...
"""
```

### ② 长函数 docstring 必须有「调用链」+「数据流向」

```python
def compress_messages(messages, max_tokens):
    """把消息列表按预算裁剪，保留最近的若干条。

    【调用链】追这个函数会进入：
        1. clip_to_token_budget()  → 单条消息超长时截断
        2. estimate_tokens()       → 算每条消息的成本
    【被谁调用】
        services/chat_memory.py::ContextAssembler  ← 主路径
        services/evals/runner.py                   ← 评测
    【数据流向】
        入：messages（来自 chat_messages 表）、max_tokens（预算）
        出：(kept, stats) → kept 拼进 prompt；stats → 前端用量面板
    【关键规则】
        1. 从【后】往前保留 —— 最近的消息最重要
        2. 单条消息最多占预算的 1/3
    """
```

三个字段固定写法：
- **【调用链】**：本函数内部会进入哪些函数（跨文件写 `模块.py::函数名`）
- **【被谁调用】**：上游是谁（方便反查"改这里会影响谁"）
- **【数据流向】**：入参从哪来、出参到哪去

### ③ 函数体内按「步骤」分块

```python
    # ── 步骤 1：统计保留区里已有的 tool_use / tool_result ──
    ...
    # ── 步骤 2：处理约束 A —— 有结果但没调用，往左把调用方拉进来 ──
```

长函数里每 5~15 行一个分块标记，扫一眼就知道这段在干什么，不必逐行读。

### ④ 什么时候写、写多细

| 情况 | 写法 |
|---|---|
| 叶子函数（如 `estimate_tokens`） | 只写【调用链】"无 —— 最底层"，重点是换算规则 |
| 中等函数（10~30 行） | 【调用链】+【被谁调用】+ 1~2 个分块 |
| 长函数（30 行以上） | 全套：【调用链】+【被谁调用】+【数据流向】+【关键规则】+ 分块 |
| 兜底函数（fallback_*） | 必须写清"为什么需要兜底、什么情况下走这里" |
